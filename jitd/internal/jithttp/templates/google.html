Connect Google

jitd signs in to Google as a service account that holds the Groups Admin role in your Workspace or Cloud Identity account. It can manage groups and nothing else: no mail, no files, no users, and no domain-wide delegation. Steps 1 to 3 are in the Google Cloud console; step 4 is in the Google Admin console and needs a super admin.

  1. Enable the Cloud Identity API. In the Google Cloud console, pick the project that will hold jitd's service account, or create one. Then open the Cloud Identity API in that project and click Enable.
  2. Create a service account. Open IAM & Admin → Service accounts and click Create service account. Name it jitd and click Done: it needs no roles in the project, so skip the optional steps. Copy its address from the list, something like jitd@my-project.iam.gserviceaccount.com.
  3. Make a key. Click the service account, open its Keys tab, then Add key → Create new key → JSON. A file downloads; that file is the key.
    Google says key creation is disabled

    Organisations created since May 2024 start with the organisation policy Disable service account key creation (iam.disableServiceAccountKeyCreation) switched on. Someone with the Organization Policy Administrator role can turn it off for this one project, under IAM & Admin → Organization policies.

  4. Give it the Groups Admin role. In the Google Admin console, signed in as a super admin, open Account → Admin roles. Point at Groups Admin and click Assign admin, then Assign service accounts. Paste the service account's address, click Add, then Assign role. Google can take a few minutes to apply it.
  5. Paste the key here.

    How it works

    • An approval flow can name Google groups, with or without a posture attribute: fill in Google groups on the flow's page, by group address. An approval adds the requester to each group; jitd takes them out when the access expires or is revoked.
    • That reaches whatever Google gates by group: Google Cloud roles, apps people sign in to through Google, shared drives.
    • Not Tailscale access. Tailscale reads Google groups only every 40 minutes, so a group would open access late and close it late. Use a flow's posture attribute for that.
    • The requester's Tailscale login is used as their Google address. There is no lookup: if the two differ, Google refuses the add and the approval fails.
    • Someone who was in the group already stays in it: jitd only removes what it added.
    • Dynamic groups, whose members come from a query, cannot be granted.
    • jitd removes members itself, so it has to be running to do it. If a removal keeps failing, admins see it on every page.

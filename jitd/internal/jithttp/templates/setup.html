How to set up the credentials

jitd needs an API credential to set posture attributes on devices (that is how an approval turns access on) and to read the policy file (to resolve group: principals, check each flow against the policy and mark the policy snippet). It reads the credential from a file on the host it runs on, so none of the admins here ever sees it.

Approvals use custom posture attributes with an expiry, set through the Tailscale API; see Posture attributes API with expiry; it needs a Premium or Enterprise plan.

  1. In the Tailscale admin console go to Settings → Trust credentials → New credential and pick OAuth. Give it a description such as jitd and, on the Scopes step, these scopes: Devices → Posture attributes: Write and Policy file: Read. Copy the client ID and the secret; the secret is shown once.
  2. On the host running jitd, put them in {{.Credentials.File}}, one per line, readable only by the user jitd runs as (chmod 600): 
    TS_OAUTH_CLIENT_ID=...
TS_OAUTH_CLIENT_SECRET=tskey-client-...
    An API access token (TS_API_KEY=tskey-api-...) works too, but it expires after at most 90 days; an OAuth client does not.
  3. Come back here and click Check again. No restart is needed; jitd re-reads the file and starts using the new credential if the checks pass.

Variables set in jitd's environment are used for anything the file does not set (for example when it runs in a container). Another file can be chosen with jitd -env-file.
